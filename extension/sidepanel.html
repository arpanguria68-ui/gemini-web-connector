Gemini Connector

Your own Gemini session, through a local OpenAI-compatible proxy.

Unofficial. Rides your browser login, not a Google API. Personal use only. See Disclaimer.

Where do I find my key?

It was printed at the end of python setup.py. It's also in config.json under api_keys. Same key for every browser on this computer. Each other person has their own, made by their setup.

Reads cookies and tokens from your signed-in Gemini tab. Nothing leaves this machine except to your own local helper or a file you save.

Ready. Open Gemini, sign in, refresh, then Inspect.

Sync to proxy sends the session to the local helper (npm run ui), which writes gemini-auth.json and updates config.json. Then restart the proxy. Save file… is the manual route from the PDF.

Stored in this browser profile (extension storage) only.

API key

The key belongs to your proxy, not to a browser or Google. It was made on this computer by setup.py (16 random bytes) and lives in api_keys in the proxy's config.json. Every browser and tool on this computer can use the same key; you paste it once per browser. Another person runs their own setup and gets their own key; never share yours.

Add: new key for this browser; other browsers and tools keep working, and you can revoke this one later by deleting it from api_keys. Replace: one new key, all old keys stop working (use if a key leaked); update other browsers and tools afterwards. Both need your current key and a proxy restart.

ModelTimeResult

      
Runs every model one at a time with a short pause (parallel traffic raises the flag risk). Same tiny prompt, single run, so treat times as rough; long prompts and thinking models take longer. Times are saved and shown in the Model list.

      
Times swing a lot between runs (the same model measured 4s and 11s), so rerun before drawing conclusions. Best quality: 3.1-pro. Longest output: 3.5-flash-thinking. A timeout usually means one upstream call hung; rerun that model.

System working

      
Gemini's web app sends a cookie, a session id and a rotating security token with every request. The proxy replays that handshake, so Google sees your login, not an API client.

      
    
        
  1. Sign in at gemini.google.com.
    2. 
        
  2. This extension reads cookies, sapisid, xsrf_token, gemini_bl from the live tab (Session tab).
    3. 
        
  3. Sync to proxy writes gemini-auth.json and updates config.json through the local helper. Restart the proxy.
    4. 
        
  4. Proxy (gemini_web2api.py, port 8081) converts OpenAI JSON to Gemini's internal format.
    5. 
        
  5. Chat tab and your tools call /v1/chat/completions with your API key.
    6. 
      

      
Chrome login → this extension → helper → gemini-auth.json + config.json
Chat tab / your tools → Proxy :8081 (API key) → gemini.google.com

    

    

      
API keys

      

        
Made bysetup.py on your computer (random), or Settings → API key later. Never by Google.

        
Stored inProxy config.json → api_keys (a list; several keys allowed). Each browser keeps its own copy in extension storage.

        
Checked byProxy on every /v1 call (Authorization: Bearer), and helper on Sync/key changes.

        
Your browsersSame key (or one each via “Add a key”).

        
Other peopleTheir own setup, their own key, their own Google account.

        
Changes applyAfter restarting the proxy (keys load at start).

      

    

    

      
Reading the health check

      

        
HealthyPro replies with label gemini-3.1-pro.

        
DegradedPro answered by Flash: cookie not honored.

        
400 / xsrfToken expired. Refresh Gemini tab, Sync, restart proxy.

        
null contentSession expired or rotated.

        
UnreachableProxy not running. It has no daemon mode.

      

      
Speed: most models answer short prompts in 4–20s. If every call takes ~100s, the proxy is running the unpatched urllib path; use the patched gemini_web2api.py (shared httpx client), which logs Upstream ok in X.Xs per request. Run the benchmark in Settings to compare models.

      
Uptime: machine must stay awake with the proxy running (disable sleep, always-on box, or cheap VPS). Off your Wi-Fi: Tailscale (recommended), Cloudflare Tunnel or ngrok. Never forward a public port, and keep a strong API key.

    

  


  
  

    

      
Disclaimer

      
This is not an API. It is your browser's login, automated.

      
Account may be flagged. Google's abuse detection expects one human at a human pace. Heavy or scripted traffic raises the odds. It may also conflict with Google's terms of service. Use at your own risk.

      
It can break without warning. The proxy chases Google's frontend, with no notice and no upgrade path you control.

      
No SLA, no support. If it fails, the fix is re-syncing the session.

      
The session is a live login. gemini-auth.json is not an API key. Never commit, share or paste it anywhere, including chats. If leaked, sign out that session at myaccount.google.com.
